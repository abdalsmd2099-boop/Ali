OB30 delivers, OB1 decides. OB30 only moves words to and from the bus every 10 ms. OB1 runs the logic once per cycle, in the order below, which is the data flow of one cycle. Your cyclic interrupt may be named OB33, the content is the same.

2. Single move proven

Robot move screen. Enable on, AUTO off. This is the path every other function uses at the end, one move at a time.

  1. You type X Y Z RotZ RotY, block 1 or 2, override 10 "DB_RobotMove".Man.udtReq.udtPose.rX … rRotY, .intBlock, .intOverride radius for block 3/4: .aorPar[1]
  2. MOVE, momentary "DB_RobotMove".Man.xStart
  3. FC_MoveSelect in hand mode copies the typed request and the start Req := Man.udtReq xReqStart := Man.xStart
  4. FB_RobotMove step 5, checks: block 1 … Cfg.intBlocksInPrg20 else error 1; pose inside the limits else 2 or 3; radius > 0 for blocks 3 and 4 else 4; robot ready and referenced and access else 5; not moving and program not running else 6; comm OK else 7; override > 0 else 8; program 20 initialized or finished else 14
  5. Step 10, write: Srl.Pose[1..5] from the pose, Srl.Par[1..3] from aorPar, Srl.Par[4] = run number, Srl.Gate[n] = TRUE with GateEnable, Cmd.Override from the request, Cmd.ProgramNumber = 20 "DB_App".Srl.*, "DB_App".Cmd.Override, .ProgramNumber
  6. Step 15, program stop (engine v0.5, 2026-11-03): only when the robot shows "repositioning required" after a jog. State.xPrgStop goes to the stop pin of network 2 until the robot shows initialized without the request, then off. Without it the robot would first drive back to the point where it left the old path (manual 6.6, 9.10). 2 s without the answer → error 15 "DB_RobotMove".State.xPrgStop OB30 NW2: stop := Cmd.Stop OR State.xPrgStop
  7. OB30 sends the words on the next 10 ms tick: pose to 114–118, parameters to 119–122, gates to 123. Then the engine sets "DB_App".Cmd.Start, network 2 puts it on the bus together with ReadyToStart
  8. Robot runs program 20: the IF of block n is true, SET_MOTIONSET, LIN_VAR POSE[51] (or CIRC_VAR), REAL[71] := n, then REAL[72] := REAL[54], END_PROG waits for the movement
  9. Step 20 and 40: the engine must see program running (else error 11 after 3 s), then program finished (move timeout → 12). The step 40 echo check covers very short moves. "Program finished" is the normal state of program 20 between two moves, the next start works from it, nothing clears it
  10. Step 60, echo: REAL[71] must equal the block (else 10), REAL[72] must equal the run number (else 13). Then xDone for one cycle, udtPoseAtEnd = actual pose, start bit and gate off "DB_RobotMove".State.xDone, .udtPoseAtEnd, .intRunNr, .intBlockActive
  11. While it runs: Enable falls → 20, robot fault → 21, access lost → 22. RESET clears the error "DB_RobotMove".Man.xReset

4. Scan cube in the plc

Automatic screen. Enable on, AUTO on, job = 1, override 10. Poses 2 … 7 taught, safe Z set. First in simulation (old screen, PO 1.9), then real.

  1. START, momentary "DB_RobotJob".Man.xStart, gated in OB1 by Man.intJob = 1
  2. FB_ScanCubeJob step 10, build and check: poses 2 … 7 valid else job error 1; safe Z > 0 else 2; engine idle and no error else 3; every pose of the list through FC_PoseCheck else 4 with the move number in active. Nothing is pushed if a check fails
  3. The list, 13 moves, 14 with home: start, approach, corner 1, side 1, turn at c2, side 2, turn at c3, side 3, turn at c4, side 4, turn at c1, lift to safe Z, start, home. A side is the next corner with the orientation of the corner before, a turn takes the own orientation. All block 1, blend 0, override from the screen, intId = list index
  4. Step 20: clear the queue, push one move per cycle "DB_RobotJob".Cube.xClear, .xPushReq, .udtPush → FC_JobMux → Push → FB_MoveQueue

5. Circle and drum new

Program 20 blocks 3 and 4 are the circle: from where the robot stands, an arc of the given radius to the end point POSE[51], in the plane XY, counter-clockwise (3) or clockwise (4). Only X and Y of the end point are used, so the end Z must be the current Z. Positive radius is the shorter arc. Never a half circle with the end-point form. A full circle: four quarters with blocks 3 and 4, or one line with block 6 or 7, the center in POSE[51] and the angle 360 in REAL[52] (2026-11-06, drum checklist part F).

Before anything with a circle: the add-on Circle license and the activation in the MOVISUITE software module (CIRC_VAR must appear in the New Block list), program 20 lines 11–20, "DB_RobotMove".Cfg.intBlocksInPrg20 = 4, and a radius field on the Robot move screen bound to "DB_RobotMove".Man.udtReq.aorPar[1].

By hand, the first test

  1. Read the actual pose X0 Y0 Z0 RotZ0 RotY0
  2. Type X = X0 + r, Y = Y0 + r, Z = Z0, RotZ = RotZ0, RotY = RotY0, radius = r (300 for the first try), block 3, override 10, MOVE: a quarter circle counter-clockwise
  3. Type X0, Y0, same radius, block 4, MOVE: a quarter circle clockwise, back to the start
