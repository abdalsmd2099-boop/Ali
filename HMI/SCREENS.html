Switch positions for every step of tomorrow

Three switches decide what works. Two are ours, one belongs to the robot. The robot can jog and reference only in its manual mode, and it runs a program from the PLC only in its automatic mode (manual 6.1.1). From step 1a on, FB_RobotMode in OB1 sets the robot's mode by itself: automatic is the rest state, manual while a jog or home button is held and nothing of ours moves, automatic again half a second after the button is released and the robot stands still. Until that block is in the PLC, the old screen's automatic switch does it by hand: off for jogging, on for every move.

A button in the wrong position does nothing, that is wanted. MOVE with the robot in manual gives engine error 5. A jog button with the robot in automatic does nothing. A MOVE inside the half second after a jog gives engine error 5 too: RESET, MOVE again. Pause and stop on the old screen stay off all day.

5. Ladder: jog X and home X

The pattern for one axis. You copy it for Y, Z, RotZ and RotY with the table at the end. Tomorrow you jog with the old screen as it is. These rungs come in when you move jog and home onto the manual screen.

What the bus wants, from the manual

Jog is a levelPO 3.0 … 3.11. The axis moves while the bit is set, stops when it falls. One jog signal selects jog mode by itself (6.1.4, 13.6.1).
Home is an edgePO 2.10 … 2.14 "start referencing axis n". The rising edge starts the reference travel of FCB 12 in the drive, the referenced bit PI 2.10 … 2.14 comes at the end (6.7).
Only in manualJog mode and referencing mode are possible only in operating mode manual, PO 2.0 off. In automatic the robot ignores them (6.1.1).
No signal set at a resetBefore a fault is acknowledged, no jog and no referencing signal may be set, or the robot moves at the acknowledge (6.2, 6.7). The rungs below drop every signal when the fault comes.

The DB the rungs use

One new small DB. The screen writes the requests, the rungs write the permissions and the edge memories. Nothing existing changes. File DB_RobotHand.scl in the folder.

DATA_BLOCK "DB_RobotHand"
{ S7_Optimized_Access := 'TRUE' }
VERSION : 0.1
// hand screen: jog and home requests from the hmi, permissions from the ob1 hand networks.
// writers:  hmi -> Jog.*, Home.xX .. xRotY      ob1 hand networks -> the rest
NON_RETAIN
   VAR
      Jog : STRUCT                       // hmi momentary buttons: press 1, release 0
         xXPos, xXNeg : Bool;            // joint 1
         xYPos, xYNeg : Bool;            // joint 2
         xZPos, xZNeg : Bool;            // joint 3
         xRotZPos, xRotZNeg : Bool;      // joint 4, r1
         xRotYPos, xRotYNeg : Bool;      // joint 5, r2
      END_STRUCT;
      Home : STRUCT                      // hmi momentary buttons
         xX, xY, xZ, xRotZ, xRotY : Bool;
         xXEdge, xYEdge, xZEdge, xRotZEdge, xRotYEdge : Bool;   // edge memories of the p contacts
      END_STRUCT;
      xRobotManual : Bool;               // rung 1: robot healthy and in manual
      xHandOK : Bool;                    // rung 2: hand actions allowed. hmi: jog and home buttons grey when false
      tpHomeX, tpHomeY, tpHomeZ, tpHomeRotZ, tpHomeRotY : TP_TIME;   // the 500 ms start pulses
   END_VAR
BEGIN
END_DATA_BLOCK

Rung 1 – the robot is healthy and in manual

Series: comm ok, ready, not fault, access granted, not automatic → coil "DB_RobotHand".xRobotManual. All five are feedback from the robot, not our commands. A fault drops it in the same cycle, and with it every jog and home signal.

Rung 2 – hand actions allowed

Series: Enable switch, not AUTO, engine not busy, not in referencing mode, rung 1 → coil "DB_RobotHand".xHandOK. Bind the jog and home buttons' "enabled" property to this bit, then they are grey when nothing may move. The robot's moving bit is not in here: jogging makes it true, it would stop its own jog.

Rung 3 – jog X positive

Series: hand ok, button X+, not button X− → coil "DB_App".Cmd.Jog_Pos_X. A level, as long as the button is held. OB30 network 2 puts it on jog_pos_J1X.

Rung 4 – jog X negative

Series: hand ok, button X−, not button X+ → coil "DB_App".Cmd.Jog_Neg_X. The mirror of rung 3. Both buttons together: nothing moves.

Rung 5 – home X, start the referencing of axis 1

Series: hand ok, button HOME X with a P contact, robot not moving → TP pulse of 500 ms → coil "DB_App".Cmd.Home_X1. The P contact gives one cycle per press, the TP stretches it to a clean edge for the robot and clears it by itself. OB30 network 2 puts it on homing_Start_X1. Referencing runs in the drive (FCB 12) until "DB_Robot".Status.aoxAxisReferenced[1] comes. During it, Status.xRefMode is true and rung 2 blocks the jog buttons.

One writer. Today the old screen writes "DB_App".Cmd.Jog_Pos_X and .Cmd.Home_X1 directly. The day rungs 3 to 5 go into OB1, the old buttons must be re-bound to "DB_RobotHand".Jog.xXPos, .Jog.xXNeg and .Home.xX, or deleted. A rung and a button on the same tag is the bug of BLOCK_MAP.md part B3.
Before homing an axis that is not referenced: jog it to the reference position with the coordinate system "Axis" ("DB_App".Cmd.Jog_Axis on), the only system that jogs unreferenced (manual 6.2, 9.5). Your own homing helper in "DB_App".Home stays as it is; rung 5 is only the plain start of one axis.
