Gantry HMI Screens V2

Four screens sorted by who stands at the panel: RUN for the operator, SETUP for the scan preparation, HAND for commissioning, DIAG for you. One status strip on all four. Every object carries its PLC tag as the blocks of PLC/ define it on 2026-11-05 (engine v0.7, cube job v0.7, select v0.3, cube buttons v0.2). The object numbers of SCREENS.html (A1 … A50, M1 … M40) stay valid; this page regroups them under new numbers T, R, S, H, D.

One writerA field or button is bound only to a tag whose writer in BLOCK_MAP.md B1 is "HMI". A block always wins against the screen.
Buttons are bitsA button writes one bit, the PLC does the rest. No HMI scripts. Today: "DB_RobotHand".Btn for the cube box; MOVE, RESET, ABORT, START still write Man.* directly.
Permission lampsEvery button that can be refused is greyed from a bit the PLC computes (Lamp.xTeachAllowed, Lamp.xGoAllowed). Nobody learns from an error number that something was not allowed.
Numbers with textsEvery number that means something has its text list next to it: TL_Step, TL_Err, TL_JobErr, TL_Move, TL_Block. The lists for v0.7 are in SCREEN_FIXES.md 2.1.
Four coloursgreen = allowed or done, grey = not allowed, yellow = waiting (steps 15, 20, 40, 50, 95), red = error. The same on all screens.
RUN SETUP HAND DIAG

The status strip, the same on all four screens

RUN, the operator

Starts and stops the scan and reads the three numbers. No typed number, no teach, no jog. The job box and the engine box of today's Automatic screen, nothing else.

SETUP, preparing a scan

The cube numbers, the switches, teaching and the two go-to moves. No START: a scan is started from RUN after the setup is complete, and the ready lamp says when it is.

HAND, commissioning

Jog and home per axis, one single move with the five target fields. MOVE is greyed while AUTO is on. This is today's Robot move screen plus the hand rungs.

DIAG, the watch table as a screen

Every row of section 8 of the engine review as a field or a lamp, so the two open errors are read here and not in TIA. No button that moves the robot. Simulation and the robot reset stay here, they are the only writes.

What changes in the PLC for this layout

Nothing for the screens as drawn: every tag exists. One step later, to close the last one-writer exception: MOVE, RESET, ABORT and START as bits in "DB_RobotHand".Btn (xMove, xReset, xAbort, xStart) and FB_CubeButtons v0.3 as their one writer, pulsing Man.xStart, Man.xReset, "DB_RobotJob".Man.xStart, .xAbort. Until then the four buttons write the Man.* tags as today, which is the documented exception of BLOCK_MAP.md.
